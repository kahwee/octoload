# Repository guidance

Octoload provides a browser upload client, Next.js/React Router handlers, and a
PostgreSQL/SQLite schema and scaffold CLI. Start with [README.md](README.md) and
[CONTRIBUTING.md](CONTRIBUTING.md); storage variants are in [docs/integrations.md](docs/integrations.md).

- Use Node 24+ and the exact pnpm version in `package.json`. Preserve the committed
  lockfile and workspace build/release-age policy.
- Keep root, `/client`, `/nextjs`, and `/react-router` exports compatible.
  Client code belongs in `src/client/`; server and storage code stays outside it.
- Schema sources are `src/templates/upload-schema.ts` (PostgreSQL) and
  `src/templates/upload-schema-sqlite.ts` (SQLite); `pnpm build` regenerates
  both embedded schema modules. Framework scaffolds are generated by
  `src/commands/init.ts`; check import paths against the selected framework.
- Preserve session-derived ownership, private defaults, and the presign → PUT →
  finalize lifecycle. Current server uploads use single PUT; do not document
  multipart processing or image-byte validation as implemented behavior.
- For source/dependency changes, run the full verification command in
  `CONTRIBUTING.md`, including coverage, PGlite, and built package/scaffold smoke tests.
- Keep PostgreSQL as the CLI default; PGlite uses its schema with `--driver pglite`.
  Preserve offline migration generation and existing app DB files.
  SQLite connections must enable foreign
  keys; keep Date/boolean row values compatible and test generated migrations.
- For README edits, run `pnpm test:docs` and check local links. It parses the
  TypeScript/JSON examples and typechecks the browser component; uploads and
  migrations still require an actual configured bucket and database.
- Keep generated `dist/` and QA logs out of commits. Publish only when authorized.
